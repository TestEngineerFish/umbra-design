# UmbraDesign · 06 写稿规则

> **这一份是 `get_syntax_guide` 发给调用模型的规则文本**，写给写稿的人或模型看。
>
> 分工：`03` 是**框架语义**（模板语言怎么解析，任何租户都一样）；
> 这一份是**写法约定**（这个租户怎么写才对）。不要把租户约定写进 `03`，
> 那会让通用框架带上 Umbra 味。
>
> 标注 🤖 的条目由 `validate_draft` 自动检查（`00` §六），你不用手工过；
> 标注 ✋ 的检查不了，必须自己守。

---

## 一、开工前

1. `get_project` 拿到租户的限额与 ds 路径
2. `search_tokens` 取你要用的取值 —— **不要凭记忆写颜色和间距**。
   `umbra-tokens.json` 是判据与取值的唯一出处，1,447 个叶子，按需检索
3. `list_components` 看有什么能复用 —— 「行尾 ⋯ 菜单」这类十处共用的件已经有了
4. 要复用就 `get_component(mode: "contract")` 取 props 契约，别去读全文

## 二、模板

### 2.1 样式一律写在 `style` 属性上 ✋

不是审美偏好，是两条实际原因（`02` §4.3）：实现侧看
`style="padding:10px 18px;background:var(--rail)"` 就能抄，
看 `class="page-header"` 还要去翻样式表。

例外只有三样，放 `<helmet>`：`@font-face`、`@keyframes`、body 重置。

### 2.2 设计系统用 `@ds` 别名 ✋

```html
<helmet>
  <link rel="stylesheet" href="@ds/tokens/colors.css">
</helmet>
```

**不要手写 `_ds/umbra-design-system-<uuid>/…` 这种真实路径。**
`write_draft` 落盘时会把 `@ds` 展开成正确的相对路径（`00` §3.2）。
落盘后的文件里没有别名，运行时不认识 `@ds`，也不需要认识。

### 2.3 洞里只能是点号路径 🤖

`{{ title }}`、`{{ user.name }}`、`{{ $index }}`、`{{ true }}` / `{{ false }}` 可以。

`{{ a + b }}`、`{{ fn() }}`、`{{ a ? b : c }}` **一律不支持**。
要算就在 `renderVals()` 里算好，起个名字暴露出来。
理由见 `02` §4.2 —— 限制成点号路径之后，「这个字从哪来」永远是一个明确的键名。

### 2.4 `dc-import` 三条 🤖

- 必须写显式闭合标签，**不能自闭合**
- `name` 相对**当前文件所在目录**，跨文件夹要写相对路径（`name="../Components/X"`），
  只写基名会解析不到
- 属性 kebab → camelCase：`secondary-label` → `props.secondaryLabel`

### 2.5 注释里不许出现标签字面量 🤖

开标签也算。会把注释提前关掉，剩下半段渲染到屏上。
要在注释里提一个标签，写成 `sc-if` 而不是 `<sc-if>`。

### 2.6 `hint-*` 属性：第一阶段写了也没用 ✋

`hint-placeholder-val` / `hint-placeholder-count` / `hint-size` 这些是**流式渲染**的配套。
第一阶段调用方是模型，一次性落盘，没有流式阶段，所以这些属性
**解析但忽略**（`03` §八）。

存量稿里的 `hint-*` 不用删（语法仍然合法），但**新稿不要写**——
`validate_draft` 会给一条 `W_HINT_IGNORED`。

## 三、逻辑类

### 3.1 契约

类名固定 `Component`，继承 `DCLogic`（运行时注入）。经典 JS，**无 `import` / `export` / TS**。
可用全局只有 `DCLogic` 和 `React`。生命周期与 React class 组件一致，少一个 `render()`。

`renderVals()` **同步**，返回一个扁平对象，就是模板的输入。
不能 `await`，不能返回 Promise，不要在里面 `setState`。

### 3.2 洞的审计，正反两遍 🤖

**正向**：模板里每一个 `{{ 根名 }}` 都要在 `renderVals()` 的顶层键里。

**每一条返回路径都要给全**，包括早返回。这一条踩过：

```js
dtpVals(s) {
  const p = s.dtp;
  if (!p) return { open: false, cells: [] };   // ← 少了 hoursRef / minsRef
  …
}
```

**反向**：`renderVals()` 返回的顶层键逐个在模板里找，
零命中的要么删、要么在注释里说出它为什么留着。

### 3.3 事件与 ref 洞给兜底 —— 建议，不是必须 ✋

```js
const NOOP = function () {};
renderVals() {
  const P = this.props;
  return { onAction: P.onAction ?? NOOP, listRef: P.listRef ?? NOOP };
}
```

> ⚠️ **这一条的地位变了。** 旧文档说裸的 `undefined` 会让整页永远画不完——
> `05` §四实测**未复现**：去掉 `?? NOOP` 后页面照常渲染，读数与修复版完全相同。
>
> 所以现在的理由只是普通的工程理由：`undefined` 传下去会让 ref 静默失效、
> 让子组件里的可选调用变成可选链地狱，排查起来费劲。**给兜底更省事，但不给不会挂。**
> 不要再为了这一条去改存量稿。

### 3.4 不要发明初始 state ✋

迁移或改稿时**只带走原稿真的写了的初始值**。「没声明」本身就是原稿的默认值。

踩过：原稿 `state` 里一个 `cap*` 键都没声明，代码靠 `s.capSkills || []` 吃 `undefined`；
"补齐"成 `capSkills: {}` 之后，`{} || []` 得到 `{}`，`f.map is not a function` 当场抛。

> **一个看起来更规矩的初始值，会把原稿的兜底路径整条绕过去。**

### 3.5 共用值在方法内取，不在模块顶层取 ✋

helmet 的外链是异步的，逻辑类的模块顶层可能比外链先执行：

```js
renderVals() {
  const UI = window.UMBRA_UI;   // ✅ 在方法内取，渲染时它一定已经到
  …
}
```

跨稿共用的常量与工厂进普通 `.js`，用经典脚本挂全局（`window.X = …`），
**不要 ES module** —— `renderVals()` 是同步的，`import()` 是异步的。

## 四、交互约定

### 4.1 状态切换靠 state，不靠 DOM

```js
filterAll: () => this.setState({ logFilter: 'all' }),
```

### 4.2 演示态给一颗切换钮

每个有多种态的模块，页头放一颗小胶囊钮切演示态（「预览空日志」这类）。
**不放进 props 面板** —— 一个状态两个入口，点下去不知道哪一个会发生。

### 4.3 跨页跳转是换文件

拆分之后页稿之间不共享 state，所以跳转写成换文件：

```js
goSettings: () => { window.location.href = encodeURI('../Umbra PC 端.dc.html') + '#perm'; }
```

⚠️ 文件名带空格与中文，`href` 必须 `encodeURI`。
**跨模块跳转逐处手改，不要批量正则** —— 那几处本来各有各的答案。

### 4.4 吐司挂在页稿级

一个全局的反馈控件不能住在一个局部的条件里。
吐司挂在模块 div 之外、**但仍在子组件的 children 之内**。

### 4.5 浮层留在子组件的 children 之内 ✋

窗口骨架那一层有 `transform: scale()`（窗口缩放），
而**有 transform 祖先时 `position:fixed` 是相对那个祖先定位的**（CSS 规范行为）。
把浮层挂到 `</dc-import>` 外面，fixed 就退回按真实视口定位 —— 面板会画到窗口框外去。

| 层 | 浮层能不能放 |
| --- | --- |
| 模块 div 之内 | 出得去，但浮层不该被模块的条件绑住 |
| 子组件的 children 之内 | ✅ 就放这里 |
| 子组件本身 | 进不去（页稿之间不共享 state） |

### 4.6 `position:fixed` 不与 `backdrop-filter` 同处一个元素 🤖

旧记录说这一对在缩放子树里会锁死主线程。`05` §4.4 **未测**（headless 的合成路径
与 macOS Chrome 不同，测了也不算数），所以保留为 `W_FIXED_BLUR` 警告。
落法照旧：保留 `fixed`，去掉滤镜，底色不透明度补偿。

### 4.7 动画只有两种

`.12s–.15s ease` 的颜色 / 描边过渡，和开关滑块位移。
运行中状态用 `@keyframes umspin` 匀速旋转。
**不做弹跳、缩放、入场动画。**

## 五、规模

一份稿控制在 **1,200 个静态元素标签以内**，超 1,500 必须拆。

> **依据是工程理由，不是浏览器限制。** 6,507 个元素的稿实测能完整渲染
> （`05` §三）。真正的两条理由：175 KB ≈ 45 K token，模型一次输出不了；
> 语义变更清单的粒度就是文件粒度，一份稿一个模块，清单才读得懂。

拆分点按这个优先级找：顶层 `<section>` / `<dc-import>` 边界 → 模块级 `sc-if` 分支
→ 逻辑类里独立的 `*Vals()` 方法。

## 六、收尾

### 6.1 `render_check` 是唯一的验收证据 ✋

`write_draft` 返回 `ok: true` **不等于稿是对的**。
标签配平、逻辑能编译、诊断干净，三项全绿也不能证明它能渲染（`04` §2.2）。

跑 `render_check`，看 `alive: true` 且 `nodeCount` 合理。
**判活只认 `1+1`，不看截图** —— 一张不对的截图和一个坏掉的页面在屏上长得一样。

### 6.2 改名之后数一次未知标签 🤖

字符串里的标签名写错不报错，只会安静地渲染成 0×0。
`W_UNKNOWN_TAG` 会报，但也自己扫一眼 0×0 的图标容器。

### 6.3 凡动过的每一份稿单独过一次 ✋

不凭「改的是同一种东西」推它们都好。

## 七、多文件稿不能双击打开 ✋

`dc-import` 用 `fetch()` 取兄弟稿，**Chrome 不允许对 `file://` 发 fetch**
（`05` §4.2 实测）。所以：

- **单文件稿**（零 `dc-import`）双击能开
- **带 `dc-import` 的稿**必须走本地 http

设计侧预览用 MCP 起的静态服务（形态 A）。
要给出去一份真·双击即开的文件，第二批会有 `bundle_draft` 把 import 内联
（`00` §九，**尚未承诺**）。

在此之前，交付给实现侧的是「目录 + 入口页 + 一条起服务的命令」。
