## 一、洞（hole）

### 1.1 语法

```
{{ path }}
```

`path` 只能是**点号路径**或字面量，**不允许任何表达式**：

| 写法 | 结果 |
| --- | --- |
| `{{ title }}` | `vals.title` |
| `{{ user.name }}` | `vals.user.name` |
| `{{ $index }}` | 列表循环里的下标 |
| `{{ true }}` / `{{ false }}` | 布尔字面量 |
| `{{ a + b }}` | ❌ 不支持，渲染成空 + 警告 |
| `{{ fn() }}` | ❌ 同上 |

### 1.2 洞出现的三个位置

**① 文本位置** —— 求值后转字符串插入。

```html
<span>{{ title }}</span>
```

**② 整值属性** —— 整个属性值就是一个洞，此时**传原始值**（数字、函数、对象、ref）：

```html
<button onClick="{{ onSave }}">     → props.onClick = vals.onSave（函数）
<svg width="{{ iconSize }}">        → props.width = 24（数字）
<div ref="{{ listRef }}">           → props.ref = vals.listRef（函数或 ref 对象）
```

**③ 插值属性** —— 属性值里混着字面文本，此时**拼成字符串**：

```html
<div style="width:{{ w }}px;color:{{ c }};">   → 字符串
<div title="共 {{ n }} 条">                     → 字符串
```

### 1.3 ⚠️ 取不到值时的行为

> ⚠️ **本节的旧定性已被推翻。** 旧版说整值属性洞取不到会让整页永远画不完。
> `05` §四实测：去掉兜底、让 `onAction` 为 `undefined`，页面**照常渲染**，
> 读数与修复版完全相同。所以下面那个"最小复现"**不再是复现**，
> 只是一个说明兜底写法的例子。

旧框架的记载：
- 文本洞取不到 → 渲染成空，控制台一条警告 ✅ 合理
- ~~整值属性洞取不到（`undefined`）→ 整页永远画不完~~ ❌ **未复现（`05` §四）**

旧版在 `PC 空态` 上记的"最小复现"（现在读作兜底写法的示例）：

```js
// 挂死
onAction: P.onAction,            // 单独打开时没人传 → undefined
// 正常
onAction: P.onAction ?? NOOP,    // 给一个空函数
```

**框架要求（仍然有效）**：
1. 任何洞取不到值只影响那一处
2. 整值属性洞取不到 → 该属性不设置（相当于没写），**不是设成 undefined**
3. 回一条结构化诊断 `E_HOLE_UNRESOLVED`，带文件 / 行号 / 洞名（`00` §四）。
   **只往控制台打等于没报——第一阶段的调用方是模型。**

**兜底写法（建议，不是必须，见 `06` §3.3）**：

```js
const NOOP = function () {};
renderVals() {
  const P = this.props;
  return {
    onAction: P.onAction ?? NOOP,
    listRef:  P.listRef  ?? NOOP,
  };
}
```

⚠️ **早返回路径也要给全**。本项目踩过：

```js
dtpVals(s) {
  const p = s.dtp;
  if (!p) return { open: false, cells: [] };   // ← 少了 hoursRef / minsRef，两个 ref 静默失效
  …
}
```

## 二、控制流

### 2.1 条件渲染

```html
<sc-if value="{{ hasBody }}" hint-placeholder-val="{{ true }}">
  <div>{{ body }}</div>
</sc-if>
```

| 属性 | 含义 |
| --- | --- |
| `value` | 条件洞，真值判断 |
| `hint-placeholder-val` | **流式阶段**（值还没算出来时）假装它是什么 |

`hint-placeholder-val` 的作用：模板先到、逻辑后到，这中间要决定「这一块先画不画」。
给 `true` 的会先画出来，给 `false` 的先不画。**按「哪种态更常见」来给**。

可以嵌套（本项目 `PC 错误卡` 嵌两层，正常）。

### 2.2 列表渲染

```html
<sc-for list="{{ rows }}" as="r" hint-placeholder-count="3">
  <div>{{ r.name }} · {{ $index }}</div>
</sc-for>
```

| 属性 | 含义 |
| --- | --- |
| `list` | 数组洞 |
| `as` | 每项的别名，循环体内用 `{{ 别名.字段 }}` |
| `hint-placeholder-count` | 流式阶段先画几行占位 |
| `$index` | 循环体内可用的下标 |

⚠️ **别名不是 vals 的键**，洞求值器要先查别名作用域，再查 vals。

### 2.3 ⚠️ hint 的两个坑（第一阶段不适用，见 §八）

1. **`hint-placeholder-count` 在「默认关着的浮层」里要写 0。**
   占位行里的别名洞全都取不到值（因为还没有数据），旧框架会因此卡住。

2. **嵌套 `dc-import` 的 `hint-size` 不要用百分比。**
   旧宿主下的观察：`hint-size="100%,280px"` → 页面空白；`hint-size="520px,280px"` → 正常；
   顶层那一个（挂窗口骨架的）用 `100%,100%` 可以。

   ⚠️ **未在新环境复现（`05` §4.4），且第一阶段不触发**——`hint-*` 解析但忽略（§八）。
   存量稿里已改成 px 的 14 处不用回滚。

## 三、子组件

### 3.1 引用

```html
<dc-import name="../Components/窗口骨架" active="日志" hint-size="100%,100%">
  <div>这段会成为子组件的 {{ children }}</div>
</dc-import>
```

- `name`：相对**当前文件所在目录**的路径，不带 `.dc.html`
- 同层引用写基名即可：`name="PC 空态"`
- 跨文件夹写相对路径：`name="../Components/X"`
  ⚠️ 旧框架里跨文件夹只写基名会**渲染成一个空占位、不报错** —— 这是最难查的一类
- 属性 kebab → camelCase：`secondary-label` → `props.secondaryLabel`
- `style` 作用在挂载点上
- **必须写显式闭合标签**，不能自闭合

### 3.2 props 传递

```html
<dc-import name="PC 空态"
  title="{{ emptyTitle }}"          ← 洞，传原始值
  secondary-label="打开日志文件夹"     ← 字面量，传字符串
  on-secondary="{{ noop }}"          ← 事件，传函数
  hint-size="520px,280px">
</dc-import>
```

子组件里用 `this.props.xxx` 取；**模板里也能直接用 `{{ xxx }}`**（无逻辑类时），
有逻辑类时 `renderVals()` 返回的同名键会覆盖 props。

### 3.3 children

子组件模板里写 `{{ children }}`，父组件标签内的内容会填进来。

```html
<!-- 窗口骨架.dc.html -->
<section style="flex:1;position:relative;">{{ children }}</section>
```

⚠️ **children 里的浮层要留在 children 之内**。
本项目踩过：窗口骨架那一层有 `transform: scale()`（窗口缩放），
而**有 transform 祖先时 `position:fixed` 是相对那个祖先定位的**。
把浮层挂到 `</dc-import>` 外面，fixed 就退回按真实视口定位 —— 面板画到窗口框外去了。

三层边界：
| 层 | 浮层能不能放 |
| --- | --- |
| 模块 div 之内 | 出得去（浮层不该被模块的条件绑住） |
| 子组件的 children 之内 | ✅ 就放这里 |
| 子组件本身 | 进不去（页稿之间不共享 state） |

### 3.4 外部 JS 组件

```html
<x-import component-from-global-scope="Namespace.Button" from="./bundle.js" hint-size="auto,40px">
  按钮文字
</x-import>
```

- `from` 必须是**字面量 URL**（解析时就要发起取文件，写洞没用）
- `component-from-global-scope` 取 `window` 上的名字，支持点号路径
- 同一个 `from` 引 N 次只取一次

## 四、逻辑类

```js
class Component extends DCLogic {
  state = { filter: 'all' };

  componentDidMount() { … }
  componentWillUnmount() { … }

  renderVals() {
    const s = this.state;
    return {
      rows: DATA.filter(r => s.filter === 'all' || r.kind === s.filter),
      setAll: () => this.setState({ filter: 'all' }),
      chipStyle: 'padding:4px 11px;border-radius:999px;' + (s.filter === 'all' ? '…' : '…'),
    };
  }
}
```

### 4.1 契约

| 项 | 规则 |
| --- | --- |
| 类名 | 固定 `Component` |
| 基类 | `DCLogic`，由运行时注入 |
| 可用全局 | `DCLogic`、`React`（不注入别的） |
| 语法 | 经典 JS，**无 `import` / `export` / TS** |
| 生命周期 | 与 React class 组件一致，**少一个 `render()`** |
| `renderVals()` | 返回一个扁平对象，就是模板的输入 |

### 4.2 `renderVals()` 的性质

- **同步**。不能 `await`，不能返回 Promise。
  → 首帧要用的共用值必须走全局脚本，不能 `import()`
- **每次渲染都会调**。不要在里面做重计算，也不要在里面 `setState`
- 返回的函数每次都是新的 —— 对 React 的 `memo` 不友好，但设计稿规模无所谓

### 4.3 ⚠️ 不要发明初始 state

迁移旧稿时：**只带走原稿真的写了的初始值**。「没声明」本身就是原稿的默认值。

本项目踩过：原稿 `state` 里一个 `cap*` 键都没声明，代码靠 `s.capSkills || []` 吃 undefined；
我「补齐」成 `capSkills: {}`，于是 `{} || []` 得到 `{}`，`f.map is not a function` 当场抛。

> **一个看起来更规矩的初始值，会把原稿的兜底路径整条绕过去。**

## 五、渲染时序

```
1. support.js 加载 → 取 React
2. 找到 <x-dc>，开始解析模板
   ├─ 每解析出一个完整标签就渲染一次（流式）
   ├─ 洞暂时无值 → 用 hint-* 占位
   └─ 遇到 <helmet> 结束标签 → 把内容搬进 <head>，开始加载外链
3. 解析到 </x-dc> → 模板树完成
4. 编译 <script data-dc-script> 的逻辑类
5. new Component()，调 renderVals()，用返回值填所有洞，整体重渲染
6. 此后任何 setState → 重调 renderVals() → 重渲染
```

⚠️ **第 2 步的 helmet 外链是异步的**，所以：
- 逻辑类的**模块顶层**（`const UI = window.UMBRA_UI`）可能比外链先执行 → 取到 undefined
- **在 `renderVals()` 内部取**才安全 —— 渲染时它一定已经到

```js
renderVals() {
  const UI = window.UMBRA_UI;   // ✅ 在方法内取
  …
}
```

## 七、给新框架的语义清单（逐条实现即可跑旧稿）

- [ ] `{{ 点号路径 }}`，三种位置（文本 / 整值属性 / 插值属性）
- [ ] `{{ true }}` / `{{ false }}` / `{{ $index }}`
- [ ] 表达式洞 → 渲染空 + 警告，**不崩、不卡**
- [ ] `<sc-if value hint-placeholder-val>`，可嵌套
- [ ] `<sc-for list as hint-placeholder-count>`，别名作用域优先于 vals
- [ ] `<dc-import name … hint-size>` + 属性 kebab→camel + children
- [ ] `<x-import component-from-global-scope from>`
- [ ] `<helmet>` 搬进 head，按解析后的绝对 URL 去重
- [ ] `class` → `className`，`for` → `htmlFor`
- [ ] 逻辑类编译：注入 `DCLogic` / `React`，隔离作用域
- [ ] `renderVals()` 同步调用，返回值填洞
- [ ] React 生命周期透传
- [ ] `data-props` 解析（面板本身是第二阶段，`01` §3.3）
- [ ] ~~流式渲染 + hint 占位~~ → **第二阶段**，第一批解析但忽略（§八）
- [ ] **错误可见**：洞名 / 文件 / 行号，**以结构化结果回给调用方**（`00` §四）

> ⚠️ 这张清单是"从零实现引擎"时用的。第一阶段**不重写引擎**——
> `support.js` 原样 vendor（`00` §一）。清单现在的用途是
> **对照检查点改后的行为有没有跑偏**。

## 八、`hint-*` 在第一阶段的处置

`hint-placeholder-val`（§2.1）、`hint-placeholder-count`（§2.2）、
`hint-size`（§3.1）三个属性都是**流式渲染**的配套——它们回答的是
"模板先到、逻辑还没到，这中间先画什么"。

第一阶段调用方是模型，一次性落盘，**没有这个中间态**。
而这套语义制造了 `04` 缺陷 #4（`hint-size` 用百分比 → 空白）
和旧自检第 7 条（默认关着的浮层里 `hint-placeholder-count` 要写 0）两个坑。

**处置：语法保留、实现推后。**

| 项 | 第一阶段 | 第二阶段 |
| --- | --- | --- |
| 解析 `hint-*` | ✅ 合法属性，不报错 | ✅ |
| 按 `hint-*` 画占位 | ❌ 忽略 | ✅ 打开流式后生效 |
| 存量稿里的 `hint-*` | 不用删，不用改 | 直接可用 |
| 新稿写 `hint-*` | 给一条 `W_HINT_IGNORED`（`00` §6.2） | 不再警告 |

> **保留语法 ≠ 保留流式实现。** 这是第一批能省掉一大块复杂度的地方，
> 而且不牺牲任何存量稿的兼容性。
