## 一、产品定义

**Umbra Studio 是一个目录工作台：打开一个目录，左边和 AI 对话，右边看选中的文件；
按文件类型给不同的预览与编辑方式；设计稿（`.dc.html`）是它最深的一种文件类型。**

判据一句话：

> **做一个和 One Claude 里「对话 + 产物」基本一样的工作台，最大的不同是产物在你的目录里，任何模型都能接。**

「在你的目录里」不是实现细节，它是一串需求的来源：项目就是磁盘上一个目录、所有文件都看得见、
版本是本地快照、变更清单是目录里一个 Markdown、PC 端断网必须可用、
文件本身就能交给任何工具打开，也能交给任何模型（通过 MCP）去改。

### 1.1 三个定位句（回答「它是什么、不是什么」）

| 它是 | 它不是 |
| --- | --- |
| 工作台：一个目录、所有文件都能看、少数类型能改、AI 对什么都能说 | 通用编辑器：每种类型做到专业工具的深度 |
| 设计工具：`.dc.html` 的创建 / 编辑 / 校验 / 体检 / 语义版本 / 变更交付，全套保留 | 代码 IDE：没有补全、终端、调试、git 面板 |
| Umbra 秘书的文件面：同一套能力通过 MCP 给秘书和外部模型 | 云端产品：不做云同步、账号共享、多人协作 |

### 1.2 和参照物的关系

| 维度 | One Claude / Claude Design | Umbra Studio |
| --- | --- | --- |
| 产物存放 | Anthropic 云端 | **你的目录**，一个项目一个目录 |
| 谁能改 | 只有 Claude | 人、应用内 AI、**任何 MCP 客户端**（Claude Code / Codex / Umbra 秘书） |
| 产物类型 | 文档 / 幻灯片 / 设计 / 网页 | 目录里的任何文件；`.dc.html` 最深 |
| 版本 | 云端历史 | 本地快照；`.dc.html` 另有四级语义 diff 与 `CHANGELOG-设计侧.md` |
| 离线 | 需要网络 | **PC 端断网必须可用** |
| 校验 | 内部做，不给用户看 | 落盘即校验 + 真浏览器体检，诊断给用户看 |
| 端 | Web / 桌面 / 移动 | 第一期 **PC + Web**，同一份前端；移动端后期走 Web 版 |

`.dc.html` 格式、`support.js` 运行时（69 KB，原样 vendor，不重写，依据 `05`）、三种编辑方式、
`dc-import` 组件化、设计系统检索 —— 这些和 Claude Design 一致的部分**全部保留**，
它们是「设计」这个类型的深度，不是被替换的东西。

## 二、使用者

| 使用者 | 用来干什么 |
| --- | --- |
| **设计侧（主）** | 建项目、写稿、调形制、看变更 —— 三种编辑方式都用 |
| 产品侧 | 看稿、看 `.md` 需求与状态清单、在同一窗口里提改动 |
| 实现侧 | 打开稿取值 + 读 `CHANGELOG-设计侧.md` —— 在同一窗口，**只读** |
| 任何要和自己目录里的文件对话的人 | 打开目录，看文件，让 AI 改 `.md`、解释图片、整理目录 |
| **Umbra 秘书** | 通过 MCP 把这里当作它的文件面：列目录、读写文件、改设计稿 |
| 外部模型客户端 | Claude Code / Codex 等直接连 MCP |

**人是第一使用者。** 界面不是可选项；结构化返回也不是可选项（秘书和外部模型都靠它）。

## 三、三种编辑方式（产品的定义性需求）

| # | 方式 | 谁在改 | 一次交互的形状 |
| --- | --- | --- | --- |
| ① | **手动改** | 人 | 预览里选中一个对象 → 改数字 / 挑颜色 / 改文案 / 改一段文字 → 文件变了 |
| ② | **选中对象后发消息给 AI** | 人指位置，AI 改内容 | 选中一个对象 → 说「这里改成 X」→ AI 改 → 人看结果 |
| ③ | **直接与 AI 对话** | AI 全程 | 说需求 → 读规则与取值 → 写文件 → 校验 → 体检 → 回报变更 |

**三条必须在同一个应用窗口里完成。**

「选中对象」按文件类型不同：`.dc.html` 里是节点；`.md` 里是文本区间；图片里是一块区域；
目录里是若干文件。会话里的「已选中」药丸要显示对象类型。方式 ②③ 对每一种类型的**最低要求**是能带上
它的上下文（路径 + 选中内容）说话；能不能真的改，见 §4.2 的矩阵。

## 四、功能需求

标注：`必须`（不做产品不成立）· `应该`（缺了能用但难用）· `可以`（锦上添花）

### 4.1 工作台与布局

| | 需求 |
| --- | --- |
| 必须 | 打开**任意目录**当项目；记住最近打开过哪些；首页是项目列表 |
| 必须 | 左会话、右预览的主结构；**预览区永远是最大面板**（R1） |
| 必须 | 从属面板按当前文件类型出现：`.dc.html` 出属性 / 诊断 / 变更 / 评论，`.md` 出大纲，图片什么都不出（R1） |
| 必须 | 会话栏可左可右、可收成一条输入条；收起时预览吃满（R2） |
| 必须 | 切换文件时只换从属面板，左栏与预览的分界线不动（R4） |
| 必须 | 布局是**按类型预设 + 可收起 + 记住每种类型上次的收放状态**，不做自由拖拽网格（R3） |
| 必须 | 窗口宽 < 1100 px 时从属面板改抽屉（R5） |
| 应该 | 目录内文件切换有页签 / 下拉，带类型图标 |

### 4.2 文件类型矩阵

这张表是产品的功能边界。每一种类型 = 预览器 + 选中桥 + 写入路径 三件套，
**每期只加一种类型，每种有验收用例**（`11` §一）。

| 类型 | 预览 | ① 手动改 | ② 选中 → AI | ③ 对话 | 期 |
| --- | --- | --- | --- | --- | --- |
| `.dc.html` | 编辑壳（点选 / 属性面板 / 源码 / 演示） | 属性面板、文字就地编辑 | 节点桥 | ✅ | 已有 |
| 目录 | 列表 / 缩略图网格，所有文件（不只稿件） | 新建 / 改名 / 移动 / 删除（回收站） | 选若干文件当上下文 | ✅ | **第一批** |
| `.md` | 渲染视图 + 源码视图切换，大纲 | 源码编辑（所见即所得是后话） | 选中段落 | ✅ | **第一批** |
| 图片 png / jpg / svg / gif / webp | 原生显示，缩放 | **不做** | 圈一块区域 + 一句话 | ✅（多模态） | **第一批** |
| 代码 / 文本 ts / js / json / css / yaml / txt | 只读高亮 | 允许改字面量，无 IDE 功能 | 选中行 | ✅ | 第二批 |
| `.html`（非 dc） | iframe，走本地 http（H1） | 无 | 点选元素带 `outerHTML` | ✅ | 第二批 |
| `.pdf` | 视图 | 无 | 无 | 文本抽取后可对话 | 可以级，不排 |
| docx / xlsx | 转 HTML 只读 | 无 | 无 | 转文本后可对话 | 可以级，不排 |
| pptx | — | — | — | — | 不做 |
| 其它二进制 | 元数据卡（大小 / 时间 / 类型 / 被谁引用） | 改名 / 移动 | — | — | 第一批（随目录） |

| | 需求 |

| 必须 | 新建项目：建目录 + 配置 + `.gitignore`；导入已有目录当项目 |

| 必须 | 对任何文件：新建 / 改名 / 移动（分组目录）/ 复制 / 删除（回收站语义，删前列出受影响的引用方） |
| 必须 | `.dc.html` 的改名 / 移动**连带修好所有 `dc-import name`**；引用查询：谁引用了我 / 我引用了谁 |
| 必须 | 改项目配置：设计系统路径、tokens / icons、元素数限额、标题 |
| 应该 | 归档项目；稿件模板库 |
| 可以 | 项目导出 / 迁移（含快照与 changelog） |

### 4.4 `.dc.html` 编辑（设计类型的深度，全部保留）

| | 需求 |
| --- | --- |

### 4.5 校验、体检与版本

| | 需求 |
| --- | --- |
| 必须 | `.dc.html`：落盘即静态校验，诊断带 `code` / 行号 / 洞名 / 改法建议；渲染体检真浏览器，判活只认 `1+1`；读数会过期；**不许误报** |

| 必须 | 工具改任何文件都不能破坏文件：`.md` 的 frontmatter、原有换行与编码原样保留（H5 的泛化） |

### 4.9 外壳、多端与分发

| | 需求 |
| --- | --- |
| 必须 | **一份前端，两个宿主**：PC 壳与浏览器跑同一份前端；前端只通过 HTTP + WS 和核心说话 |
| 必须 | 前端里所有宿主能力（选目录对话框、在访达 / 资源管理器显示、通知、外部打开）收进 **host adapter** 接口，壳和 Web 各实现一份；前端代码不直接出现 Electron / Tauri API（H7） |

## 五、硬约束

**H1 · 打开方式分两种。** 单文件稿双击就能开；带 `dc-import` 的稿必须走本地 http ——
Chrome 不允许对 `file://` 发 `fetch`。

**H2 · PC 端断网必须可用。** React、运行时、编辑器、渲染器全部本地 vendor；任何「装依赖要联网」「取 CDN」的设计都不成立。
Web 版不受此约束。

**H3 · 每种类型一个写入口。** `.dc.html` 走 `write_draft` 那条链（归一化 → `@ds` 展开 →
`__resources` 注入 → 节点地址 → 快照 → changelog）；其它文件走泛型写入口（sha256 → 快照）。
界面编辑、AI 会话、生命周期操作、MCP 调用，一个都不例外，**也不允许类型混用**。

**H4 · 引用完整性。** 改名 / 移动 / 删除任何被引用的稿都会静默打断引用，所以生命周期操作必须先能回答「谁引用了我」。

**H5 · 同样的输入给同样的结果，且不破坏文件。** 同一份内容三种方式落盘字节一致；
工具没改的部分（frontmatter、换行、编码、无关行）逐字节原样。

**H6 · 不许误报。** 撤回一条判据之前，先证明仪器没被自己消音（`04` §2.7）。

**H7 · 前端不认宿主。** 见 §4.9。这是 Web + PC + 移动能用同一份前端的前提。

**H8 · 每期只加一种类型。** 预览器、选中桥、写入路径三件套一起交，有验收用例才算一种类型做完。

## 六、AI 大脑：两条通道

沿用 2026-09-20 核实的结论（细节见 `11` §4.1）：智谱 GLM Coding Plan 订阅只能在官方指定工具里用，
所以必须有两条通道，**对上层是同一个接口**：

**通道 A · 直连（provider 适配器）**：OpenAI Chat Completions 形状，覆盖 DeepSeek、智谱通用 API、任何兼容端点。
模型名由用户填，不硬编码。图片输入：DeepSeek `deepseek-v4-flash-vision-exp`（2026-08-21，实验性）与智谱视觉模型都走这条通道【已核实，`18` §4.4】。

**通道 B · 借官方工具（复用订阅额度）**：把本机 Claude Code 当子进程跑，模型指向 GLM 的 Anthropic 兼容端点；Claude Code 本身是 MCP 客户端，接上就通。

⚠️ 判断：通道 B 依赖两个外部产品，随时可能变；通道 A 是底线，通道 B 是增益。

## 七、验收标准

第 1–24 条沿用旧版（读数口径没变，只是「应用」现在叫 Umbra Studio），新增 25–36。

### 7.1 稿件渲染

1. `Umbra 设计规范.dc.html`（1,524 元素，零 `dc-import`）**双击**打开 → 渲染正确，控制台干净
2. `Umbra PC 端.dc.html`（6,514 元素，12 个 `dc-import`）**走本地 http** → 完整渲染，`1+1` 正常
3. 同一份稿被引用 10 次的子组件 → 只取一次文件
4. 两层以上目录的 `dc-import`（`PC 端/Pages/`）→ 正常
5. 同一份文件用三种方式落盘 → 字节一致、渲染结果一致

### 7.2 诊断

6. 删掉一个 `onClick` 的洞 → `E_HOLE_UNRESOLVED`，点名洞名与行号，其余部分正常
7. 写错一个标签名 → `W_UNKNOWN_TAG`，报文件与行号
8. `dc-import` 指向不存在的文件 → `E_IMPORT_MISSING`，显式报错，不是空占位
9. 逻辑类某条早返回路径漏一个键 → `E_RETURN_PATH_GAP`，点名那条路径
10. 模板里写 `{{ a + b }}` → `E_HOLE_EXPRESSION`，拒绝落盘
11. `@ds` 展开后解析不到文件 → `E_DS_PATH`

### 7.3 变更交付

12. 不改一个字连续两次快照 → 逐字节相同
13. 只重排一个渲染等价的容器 → 只有 L4，L1/L2/L3 全空
14. 模板中间插入一个 `<div>` → 后面的节点不被全报成变更
15. 给 props 加一个 `onRetry` → 报 L1 契约级
16. 连改四版同一个 `padding` → 只报首末值

### 7.4 离线

17. 断网打开单文件稿 → 正常渲染（React 走本地副本，无 Babel）

### 7.5 生命周期

18. 空目录起步：建 1 个项目 + 3 份稿（含一份被引用的组件），改名一次、移动一次、删一次、回收站恢复一次 —— 全程只用界面
19. 上面每一步之后 `E_IMPORT_MISSING` 都是 0
20. 故意打断一处引用 → 回归能抓到

### 7.6 三种编辑方式（`.dc.html`）

21. 方式 ①：改一个 `font-size`，iframe 的 `getComputedStyle` 真的读到新值，变更清单里是一条 L2
22. 方式 ②：选中一个元素说「这里字号大一点」→ 只有那一处变
23. 方式 ③：说「把这个按钮改成 danger 态」→ 稿变了、四级分级对、一键回退能退回去

### 7.7 分发

24. 打包产物在一台没装 Node 的干净机器上，走完「新建项目 → 建稿 → 改 → 关掉重开」

### 7.8 工作台（新）

25. 打开一个**不含任何 `.dc.html`** 的普通目录（含 `.md`、图片、json）→ 首页列出、进项目直接工作台、所有文件都在目录视图里
26. 选中 `.dc.html` → 从属面板出属性 / 诊断 / 变更 / 评论；切到 `.md` → 只剩大纲；切到图片 → 无从属面板；三次切换预览区左边界像素不动
27. 会话栏收成输入条 → 预览宽度 = 窗口宽 − 输入条；窗口缩到 1000 px → 从属面板变抽屉
28. 每种类型的收放状态各自记住：在 `.md` 下收起大纲、切到 `.dc.html` 再切回来，大纲仍是收起的

### 7.9 第一批类型（新）

29. `.md`：渲染视图与源码视图切换；源码里改一行 → 落盘 → 快照 +1 → 回退能退回；frontmatter 逐字节不变
30. `.md`：选中一段说「把这段改成三点列表」→ **只有那一段**变
31. 图片：圈一块区域说「这个按钮的颜色是什么」→ AI 回答里引用了区域坐标；不支持图片的通道上，圈选入口是禁用态并说明原因
32. 目录：选三个文件说「这三个有什么关系」→ 会话上下文里有三条路径

### 7.10 MCP 与秘书（新）

33. 外部客户端 `list_files` → 返回含类型、大小、快照号；`write_file` 写 `.md` → 快照 +1；写 `.dc.html` → 被拒绝并指向 `write_draft`
34. UmbraPC 作为 MCP 客户端连上，读一份 `.md`、改一处、Studio 界面里看到快照 +1

### 7.11 多端（新）

35. 同一份前端构建产物：PC 壳里和浏览器里跑，走完「打开目录 → 看 `.md` → 改 → 回退」；前端源码里 `grep -r "electron\|tauri" src/` 只命中 host adapter 目录
36. 打包产物在没装 Node 的干净机器上走完 35 的流程
    —— 2026-09-24 部分达成（`00` §六十三）：mac arm64 / x64 的产物拷到仓库外的目录、配全新
    userData，`packtest` 34/34 走通「打开目录 → 建索引 → 体检」，体检用的是 Electron 自带
    Chromium（`browser.from=UMBRASTUDIO_CDP`），核心跑在 Electron 自带的 Node 上、不碰外部 Node。
    **未验**：win 真机（M9-6）、真 Intel Mac（本机只有 Rosetta）、一台确实没装 Node 的机器

## 八、明确不做

| 项 | 为什么 |
| --- | --- |
| 代码 IDE：补全 / 终端 / 调试 / git 面板 | 开发者已被 Cursor / Codex / Claude Code 桌面版满足，做了必输（`18` §三） |
| 每种类型做到专业深度 | 工作台不是通用编辑器 |
| 图像 / PDF 编辑 | 只看、只圈、只对话 |
| 浏览器端文件系统（File System Access API） | 只有 Chrome / Edge、没 git、没体检，等于砍掉核心（`18` §9.3） |
| 移动端原生 App | 走 Web 版 |
| 重写 `support.js` | 引擎已经有了，原样 vendor（`05`） |
| 云端同步 / 账号共享 / 多人协作 / Share 链接 | 「在你的目录里」是产品定义 |
| 自由画布、画笔 / 图形工具 | 编辑 `.dc.html` 的结构与取值，不是任意 DOM |
| 流式渲染、导出 PDF / PPTX / 切图 | 一次性落盘；交付物是文件本身 + 变更清单 |
| `bundle_draft`（内联单文件） | 两点仍未验证（`00` §九） |
