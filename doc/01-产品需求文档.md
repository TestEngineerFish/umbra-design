## 一、产品定义

**UmbraDesign 是一个跑在自己电脑上的 PC 端设计软件。**
它创建和管理设计项目，编辑设计稿；设计稿就是 `.dc.html` ——
一份文件同时是设计稿、规范出处和可运行原型。

参照物是 **ClaudeDesign**，判据一句话：

> **做一个和 ClaudeDesign 基本一样的软件，最大的不同是设计稿存本地。**

「存本地」不是实现细节，它是一串需求的来源：项目就是磁盘上一个目录、
版本是本地语义快照、变更清单是仓库里一个 Markdown、断网必须可用、
稿件本身就能交给实现侧打开取值。

### 1.1 和 ClaudeDesign 的关系

**一样的**：`.dc.html` 格式与同一份 `support.js` 运行时（69 KB，**原样 vendor，不重写** ——
依据见 `05`）；三种编辑方式；一份文件里放多种可切换的状态而不是散成十几张图；
组件走 `dc-import`，取值走设计系统检索。

**不一样的**：

| 维度 | ClaudeDesign | UmbraDesign |
| --- | --- | --- |
| 稿件存储 | 云端 | **本地目录**，一个项目一个目录 |
| 版本 | 云端历史 | 本地语义快照 + 可选 git 兜底（`07` §七） |
| 变更交付 | — | `CHANGELOG-设计侧.md` + 四级语义 diff |
| 离线 | 需要网络 | **断网必须可用** |
| 落盘校验 | — | 静态校验 + 真浏览器渲染体检，诊断带行号 / 洞名 / 改法 |
| 对外能力 | — | 同一套能力同时暴露成本地 MCP server |
| 皮肤 | — | 我们自己那套 token，不追求像素级一致 |

后四条不是附加功能，是本地存储换来的：稿和版本都在本地，才可能对任意两版做
语义比对，并把结论写成一份实现侧能读的文件。它们是这个产品和「一个画图工具」
的分界线。

## 二、使用者

| 使用者 | 用来干什么 |
| --- | --- |
| **设计侧（主）** | 建项目、写稿、调形制、看变更 —— 三种编辑方式都用 |
| 产品侧 | 看稿、看状态清单、提改动（走方式 ②③） |
| 实现侧 | 打开稿取值 + 读 `CHANGELOG-设计侧.md` —— **只读** |
| 外部模型客户端 | 通过 MCP 直接连（Claude Code / Codex 等） |
| Umbra 秘书 | 后续接同一套能力 |

**人是第一使用者。** 取舍以此为准：该有的结构化返回要有（模型和界面都靠它），
但界面不是可选项。

## 三、三种编辑方式（产品的定义性需求）

| # | 方式 | 谁在改 | 一次交互的形状 |
| --- | --- | --- | --- |
| ① | **手动选中元素编辑** | 人 | 预览里点一个元素 → 改数字 / 挑颜色 / 改文案 → 稿变了 |
| ② | **选中元素后发消息给 AI** | 人指位置，AI 改内容 | 点一个元素 → 说「这里改成 X」→ AI 改 → 人看结果 |
| ③ | **直接与 AI 对话** | AI 全程 | 说需求 → 读规则与取值 → 写稿 → 校验 → 体检 → 回报变更 |

**三条必须在同一个应用窗口里完成。** 这是和「一堆能力 + 一个 MCP」最大的差别。

## 四、功能需求

标注：`必须`（不做产品不成立）· `应该`（缺了能用但难用）· `可以`（锦上添花）

### 4.1 项目生命周期

| | 需求 |
| --- | --- |
| 必须 | 新建项目：建目录 + 配置 + `.gitignore` + 第一份稿 |
| 必须 | 打开 / 切换项目；记住最近打开过哪些 |
| 必须 | 项目可以放在**任意路径**，不限于工具目录下 |
| 必须 | 导入一个已有的稿件目录当项目 |
| 必须 | 改项目配置：设计系统路径、tokens / icons、元素数限额、标题 |
| 应该 | 归档项目（打包挪走，不删） |
| 应该 | 删除项目 —— 二次确认，进回收站 |
| 可以 | 项目导出 / 迁移（含快照与 changelog） |

### 4.2 稿件生命周期

| | 需求 |
| --- | --- |
| 必须 | 新建稿：空白骨架 / 模板 / 复制现有稿 / 把组件包一层 |
| 必须 | 改名 —— **连带修好所有引用它的 `dc-import name`** |
| 必须 | 移动 / 分组（目录）—— 同样连带修引用 |
| 必须 | 复制 |
| 必须 | 删除 —— 回收站语义，删前列出受影响的引用方 |
| 必须 | **引用查询**：谁引用了我 / 我引用了谁 |
| 应该 | 稿件模板库 |

### 4.3 编辑

| | 需求 |
| --- | --- |
| 必须 | 方式 ①：选中节点，改 style / 属性 / 文案的**字面量** |
| 必须 | 改不了的项要说清为什么（值来自洞：函数 / 引用 / 循环变量 / 计算） |
| 必须 | 拖动 / 输入的中间态**不落盘**，松手才落 |
| 必须 | 取消（Escape）、撤销（落盘后三秒内）、版本回退，三层兜底 |
| 必须 | 方式 ②：把选中节点的上下文带进 AI 会话 |
| 必须 | 方式 ③：应用内和 AI 对话改稿 |
| 必须 | 组件稿的 props 面板（`data-props` 里 `editor` 非 null 的项渲染成控件） |
| 应该 | 多宽度 / 设备预设预览；稿的深浅色切换 |

### 4.4 校验与体检

| | 需求 |
| --- | --- |
| 必须 | 落盘即静态校验；诊断带 `code` / 行号 / 洞名 / **改法建议** |
| 必须 | 渲染体检：真浏览器，判活只认 `1+1`，报元素数 / 节点数 / 404 / 控制台 |
| 必须 | 体检读数会过期（源码变了就标过期），不能拿旧读数冒充新的 |
| 必须 | 校验器**不许误报** —— 一条假的必改项能让设计侧白改上百处 |

### 4.5 版本与变更交付

| | 需求 |
| --- | --- |
| 必须 | 每次落盘打语义快照，版本序列只增不改 |
| 必须 | 四级语义 diff：L1 契约（必须改代码）/ L2 取值（照抄）/ L3 文案 / L4 等价（不用管） |
| 必须 | `CHANGELOG-设计侧.md` —— 实现侧读它就够 |
| 必须 | 回退是**向前**的操作：把旧版内容落成新的一版，历史不改写 |
| 应该 | 两版并排对比，变更处高亮 |

### 4.6 设计系统

| | 需求 |
| --- | --- |
| 必须 | 按需检索 token / 图标 / 组件契约 —— **不做全量列举**（token 有 1,200+ 叶子） |
| 必须 | 解不开的别名链照实说「链没解开」，**不猜一个值糊上去** |
| 应该 | 跨稿搜索：某个 token / 文案 / 组件被谁用了 |
| 可以 | 改 token 取值（改前必须给跨稿影响面） |

### 4.7 AI 会话

| | 需求 |
| --- | --- |
| 必须 | 会话在应用内，和项目绑定，能持久化 |
| 必须 | AI 的每一次落盘都走唯一写入口，和人改一样受校验约束 |
| 必须 | 改动可审：落盘后能看四级分级、能一键回退 |
| 必须 | 支持两条大脑通道（见 §六） |
| 应该 | 流式输出、可中断、用量显示 |

### 4.8 外壳与分发

| | 需求 |
| --- | --- |
| 必须 | 有窗口、菜单、最近项目、文件夹选择对话框 |
| 必须 | 打包产物在干净机器上双击能用，**不需要先装 Node** |
| 必须 | 退出不留孤儿进程；强杀后重开有未落盘提示，不静默丢改动 |
| 可以 | 自动更新 |

## 五、硬约束

这几条不是选择，违反了产品就是坏的。

**H1 · 打开方式分两种，各有各的限制。**
单文件稿**双击**就能开；带 `dc-import` 的稿**必须走本地 http** ——
Chrome 不允许对 `file://` 发 `fetch`。这是上一轮唯一稳定复现的挂死原因（`04`）。

**H2 · 断网必须可用。** React 与运行时在本地 vendor，落盘时注入离线映射。
任何「装依赖要联网」「取 CDN」的设计都不成立。

**H3 · 唯一写入口。** 所有落盘走同一条路：归一化 → `@ds` 展开 →
`__resources` 注入 → 节点地址 → 快照 → changelog。界面编辑、AI 会话、
生命周期操作、工具自己生成的入口页，一个都不例外。

**H4 · 引用完整性。** `dc-import name="X"` 按文件名解析。
改名 / 移动 / 删除任何被引用的稿都会**静默打断引用**，而校验要等下一次才报。
所以生命周期操作必须先能回答「谁引用了我」。

**H5 · 同样的输入给同样的结果。** 同一份内容三种方式落盘，字节一致。

**H6 · 不许误报。** 见 §4.4 最后一条。撤回一条判据之前，
必须先证明仪器没被自己消音（`04` §2.7）。

## 六、AI 大脑：两条通道（这是被合规限制逼出来的）

**【已核实 · 2026-09-20】**

| 提供方 | 直连我们自研客户端 | 说明 |
| --- | --- | --- |
| **DeepSeek API** | ✅ 可以 | OpenAI 兼容 `https://api.deepseek.com`，另有 Anthropic 兼容 `/anthropic`；支持 tools 与流式；按量计费 |
| **智谱 GLM Coding Plan 订阅** | ❌ **不可以** | 文档明写「仅限在官方支持的指定工具与产品环境中使用」，且「在除规定工具外调用 API，不可享用 Coding 套餐的额度」。官方支持的工具包含 Claude Code / OpenCode / OpenClaw 等 |
| 智谱通用 API（按量） | ✅ 可以 | OpenAI 兼容端点，和 DeepSeek 同一条通道；但这是按量计费，用不到订阅额度 |

所以必须有两条通道，缺一条就少满足一半：

**通道 A · 直连（provider 适配器）**
我们自己跑 agent 循环，走 OpenAI Chat Completions 形状（两家都支持，也便于以后加别家）。
覆盖：DeepSeek 按量、智谱通用 API 按量、以及任何 OpenAI 兼容端点。
模型名由用户在配置里填，**不硬编码** —— 各家模型迭代很快。

**通道 B · 借官方工具（复用订阅额度）**
应用把本机已装的 **Claude Code** 当子进程跑（headless），
把它的模型指向 GLM Coding Plan 的 Anthropic 兼容端点。
这样客户端是 Claude Code，订阅额度是**合规使用**的；
而 Claude Code 本身就是 MCP 客户端 —— 我们已经是 MCP server，接上就通。

需求层面的判据：**两条通道对上层是同一个接口。** 界面上只是「用哪个大脑」，
切换不改变会话形状、不改变改动可审的口径。

⚠️ 一条判断（不是结论）：通道 B 依赖 Claude Code 的 headless 行为与 GLM 端点，
两边都是外部产品，随时可能变。所以通道 A 是底线能力，通道 B 是增益。

## 七、验收标准

前 17 条沿用旧版（都是实测过的读数口径），后 6 条是新定位加的。

### 7.1 稿件渲染

1. `Umbra 设计规范.dc.html`（1,524 元素，零 `dc-import`）**双击**打开 → 渲染正确，控制台干净
2. `Umbra PC 端.dc.html`（6,514 元素，12 个 `dc-import`）**走本地 http** → 完整渲染，`1+1` 正常
3. 同一份稿被引用 10 次的子组件 → 只取一次文件
4. 两层以上目录的 `dc-import`（`PC 端/Pages/`）→ 正常
5. 同一份文件用三种方式落盘 → 字节一致、渲染结果一致

### 7.2 诊断

6. 删掉一个 `onClick` 的洞 → `E_HOLE_UNRESOLVED`，点名洞名与行号，其余部分正常
7. 写错一个标签名 → `W_UNKNOWN_TAG`，报文件与行号
8. `dc-import` 指向不存在的文件 → `E_IMPORT_MISSING`，**显式报错，不是空占位**
9. 逻辑类某条早返回路径漏一个键 → `E_RETURN_PATH_GAP`，点名那条路径
10. 模板里写 `{{ a + b }}` → `E_HOLE_EXPRESSION`，拒绝落盘
11. `@ds` 展开后解析不到文件 → `E_DS_PATH`

### 7.3 变更交付

12. 不改一个字连续两次快照 → 逐字节相同
13. 只重排一个渲染等价的容器 → 只有 L4，L1/L2/L3 全空
14. 模板中间插入一个 `<div>` → 后面的节点**不被全报成变更**
15. 给 props 加一个 `onRetry` → 报 L1 契约级
16. 连改四版同一个 `padding` → 只报首末值

### 7.4 离线

17. 断网打开单文件稿 → 正常渲染（React 走本地副本，无 Babel）

### 7.5 生命周期（新）

18. 空目录起步：建 1 个项目 + 3 份稿（含一份被引用的组件），
    改名一次、移动一次、删一次、回收站恢复一次 —— 全程只用界面
19. 上面每一步之后 `E_IMPORT_MISSING` 都是 **0**
20. 故意打断一处引用 → 回归能抓到

### 7.6 三种编辑方式（新）

21. 方式 ①：改一个 `font-size`，iframe 的 `getComputedStyle` 真的读到新值，
    变更清单里是一条 L2
22. 方式 ②：选中一个元素说「这里字号大一点」→ **只有那一处**变
23. 方式 ③：说「把这个按钮改成 danger 态」→ 稿变了、四级分级对、一键回退能退回去

### 7.7 分发（新）

24. 打包产物在一台没装 Node 的干净机器上，走完「新建项目 → 建稿 → 改 → 关掉重开」

## 八、明确不做

| 项 | 为什么 |
| --- | --- |
| 重写 `support.js` | 引擎已经有了，原样 vendor（`05`）。改它等于接管一个 69 KB 的运行时 |
| 云端同步 / 账号 / 多人协作 | 「存本地」是产品定义的一部分，不是过渡形态 |
| 像素级复刻 ClaudeDesign 的皮肤 | 形制照它，配色和密度用我们自己那套 token |
| 通用网页编辑器 / 自由画布 | 我们编辑 `.dc.html` 的结构与取值，不是任意 DOM |
| 流式渲染 | 一次性落盘，配合校验与快照 |
| 导出 PDF / 切图 | 交付物是稿本身 + 变更清单 |
| 删除稿件的「彻底删除」默认路径 | 默认进回收站；清空要单独二次确认 |
| `bundle_draft`（内联单文件，形态 B） | 两点仍未验证，从第一批起就没承诺（`00` §九） |
