# Umbra Studio（原名 UmbraDesign，2026-09-23 转向）

**一个目录工作台。** 打开一个目录，左边和 AI 对话，右边看选中的文件；按文件类型给不同的预览与编辑方式；
设计稿 `.dc.html` 是它最深的一种文件类型 —— 一份文件同时是设计稿、规范出处和可运行原型。

判据：**做一个和 One Claude 里「对话 + 产物」基本一样的工作台，最大的不同是产物在你的目录里，任何模型都能接。**
三种编辑方式（手动改 / 选中后让 AI 改 / 直接和 AI 说）都在同一个窗口里完成。

同一套能力也暴露成本地 MCP server：Claude Code / Codex 直接连，Umbra 秘书把它当文件面。
第一期 PC + Web 同一份前端；仓库 / 目录 / MCP 名的改名是 `12` M7-1，改完前文件名里仍会看到 Umbra Studio。

**先读 `01-产品需求文档.md`**（要什么、硬约束、验收标准），
排期看 `11-路线图与分期.md`，进度看 `12-待办清单.md`。
接手这个项目的 Agent 先读仓库根的 `CLAUDE.md`。

## MVP（第一批，八件）

1. **MCP server 骨架** —— Node + TS，stdio，统一返回信封（`00` §二、§四）
2. **租户与 `@ds`** —— `project.json`、`@ds` 落盘时展开（`00` §三）
3. **检索类工具** —— `search_tokens` / `get_token` / `list_components` /
   `get_component` / `get_syntax_guide`（`00` §5.1）
4. **唯一写入口** —— `write_draft` / `patch_draft`，归一化落盘（`00` §5.2）
5. **`validate_draft`** —— 静态校验，诊断带 `code` / 行号 / 洞名 / **改法建议**（`00` §六）
6. **`render_check`** —— Playwright + headless Chromium，判活只认 `1+1`（`00` §七）
7. **语义 diff** —— `snapshot_draft` / `diff_drafts` / `get_changes_since`
   + `CHANGELOG-设计侧.md`（`07`）
8. **形态 A** —— 静态服务 + `build_index` 生成入口页（`01` §4.2）

**第一个验收用例**：`Umbra 设计规范.dc.html` —— 1,524 个元素、零 `dc-import`、
用到几乎所有语法特性，而且**双击就能开**（`05` §三实测通过），
渲染结果可以逐屏对照。

## 五条最值钱的经验

前三条来自上一轮的排查，后两条来自本轮的重测。

1. **渲染失败必须说出是哪个文件、哪一行、哪个洞。**
   第一阶段调用方是模型——**只往控制台打等于没报**，必须结构化回给它。

2. **判活只认 `1+1`，不看截图。**
   一张不对的截图和一个坏掉的页面在屏上长得一样。

3. **一条说得通的解释 ≠ 一个被证明的原因。**
   上一轮五次宣布根因，五次被推翻，共同的错都是拿"改完之后好了"当证明。

4. **先问"这个现象是在什么环境下测出来的"。**
   上一轮推翻的两条缺陷，错不在观察，在于观察是在一个带注入层和预览通道的宿主里做的，
   而结论被当成了 `.dc.html` 格式本身的性质。换个环境重测一次，比二分十几轮便宜。

5. **「双击即开」只对单文件稿成立。**
   `dc-import` 用 `fetch()` 取兄弟稿，Chrome 不允许对 `file://` 发 fetch。
   这是本轮唯一稳定复现的挂死原因，而四份旧文档一条没提。
