> 旧框架六个缺陷的**重新定性**，以及上一轮排查里学到的方法。

## 一、六个缺陷的现状

| # | 旧定性 | 现状 | 依据 |
| --- | --- | --- | --- |
| 1 | 整值属性洞取不到 → 整页永远画不完 | **未复现** | `05` §四 |
| 2 | 落盘方式会影响渲染结果 | **无法复现**（需旧宿主）；已从工程上堵死 | `05` §4.3 |
| 3 | 超过约 1,500 元素静默不渲染 | **推翻** | `05` §三 |
| 4 | 嵌套 `dc-import` 的 `hint-size` 用百分比 → 页面空白 | **未测**；第一阶段不触发 | `05` §4.4 |
| 5 | 跨文件夹 `dc-import` 只写基名 → 静默空占位 | **部分成立**，且有更大的原因 | `05` §4.2 |
| 6 | `fixed` + `backdrop-filter` 在缩放子树里锁死主线程 | **未测**；保留为警告 | `05` §4.4 |
| **7** | （旧文档未记载） | **多文件稿在 `file://` 下必然失败** | `05` §4.2 |

### 1.1 缺陷 #1 —— 未复现

`PC 空态.dc.html` 去掉 `?? NOOP` 兜底、让 `onAction` 为 `undefined`，
页面照常渲染，读数与修复版**完全相同**（29 节点，`1+1` 正常）。

**处置**：兜底降级为建议（`06` §3.3）。但仍保留两条框架要求：
洞取不到只影响那一处；整值属性洞取不到时该属性**不设置**，不是设成 `undefined`。
诊断走 `E_HOLE_UNRESOLVED`。

### 1.2 缺陷 #2 —— 无法复现，但已堵死

旧版自己注明「这条还没自洽」（`PC 空态` 的修复也是脚本落盘的，而它渲染了）。

`05` §1.1 给出一个更可能的解释（**判断，非结论**）：`support.js` 里有
`window.__resources` / `window.__resourceBlobs` 宿主注入钩子，
旧框架本来跑在带注入层和预览缓存的宿主里。旧宿主不在我们手上，测不了。

**处置**：不必查根因。MCP 是唯一写入口，强制归一化落盘
（UTF-8 无 BOM / LF / 末尾单个换行），整类可能一次堵死。
`01` §六第 5 条保留为对归一化落盘的验收。

### 1.3 缺陷 #3 —— 推翻

| 稿 | 元素标签 | 打开方式 | 结果 |
| --- | --- | --- | --- |
| `Umbra 设计规范` | 1,524 | `file://` | ✅ ALIVE，2,307 节点，控制台 0 条 |
| `Umbra PC 端` | 6,514 | `http://` | ✅ ALIVE，12.1 s，截图逐项核对无误 |

旧记录的失败样子是「不报错，退回按页显示源码，中文乱码」。
稿子头部有 `<meta charset="utf-8">`，`support.js` 一进来就 `hideRawTemplate()`——
**乱码 + 显示源码 = 文件没有被当作 HTML 解析**，那是旧宿主的预览通道
按 `text/plain` 发出来的。

**处置**：阈值保留（1,200 警告 / 1,500 硬拆），**依据改成工程理由**：
模型一次输出不了 175 KB；语义变更清单的粒度就是文件粒度。见 `00` §6.3。

### 1.4 缺陷 #5 —— 部分成立，但更大的原因是 #7

在 `file://` 下**所有** `dc-import` 都是空占位，与写基名还是写相对路径无关。
换成 http 之后，写对路径的全部正常。

所以旧记录的"跨文件夹只写基名会静默空占位"在 http 下仍然成立
（运行时默认按同层兄弟查找），校验要留：`E_IMPORT_MISSING`，
报「找不到 X，从 Y 解析」，**不是空占位**。

### 1.5 缺陷 #7 —— 本轮唯一稳定复现的挂死原因

```
[dc-runtime] sibling fetch for "PC 折叠栏" threw:
  ./PC%20%E6%8A%98%E5%8F%A0%E6%A0%8F.dc.html  TypeError: Failed to fetch
  at ensureFetched (support.js:1651)
```

`support.js` 用 `fetch()` 取兄弟稿，Chrome 不允许对 `file://` 发 fetch。
这不是 bug，是安全策略。**四份旧文档一条没提，而它比前六条加起来更要紧**——
它意味着 F1（双击即开）与 F4（组件复用）在现行浏览器策略下互斥。

**处置**：`01` §4.1 把打开方式拆成两种；交付走形态 A（目录 + 入口页 + 静态服务）。

## 二、排查方法 —— 原样保留，并加一条

上一轮学到的四条纪律一条没错。它们是这批文档里最值钱的部分。

### 2.1 判活只认 `1+1`

截图会骗人：它重渲染 DOM，`transform: scale()` 和跨源样式表都恢复不了，
**一张不对的截图和一个坏掉的页面在屏上长得一样。**

`1+1` 能分开「卡在 JS」与「画得慢」。`render_check` 就是这么实现的（`00` §7.1）。

### 2.2 不报错的挂起只能二分

标签配平、逻辑能编译、控制台干净——这三项全绿也不能证明它能渲染。
**唯一的证据是它真的画出来了。**

所以 `write_draft` 返回 `ok: true` 不是验收，`render_check` 的
`alive: true` + 合理的 `nodeCount` 才是。

### 2.3 一个读数在能重复两次之前不算数据

上一轮同一个写法先后得出过相反结论。**量不准时先修尺子，不要先改稿。**

### 2.4 先校准仪器

上一轮两次把资产路径规则写反，根因是**用错了仪器**：
拿宿主注入的重复引用当成了页面的真实解析结果。
决定性的一幕：**副本删完之后，那些警告仍然在印那些路径**——它印的文件已经不存在了。

> 判断相对引用到不到位，要看 `document.styleSheets` 里
> **真实解析出的 href 与它的 `cssRules` 条数**。
> `render_check` 的 `styleSheets` 字段就是为此而设（`00` §7.2）。

### 2.5 一条说得通的解释 ≠ 一个被证明的原因

上一轮五次宣布根因（嵌套 `sc-if` / `ref` 洞 / `fixed` / 资产路径写反两次 / 重复 bundle），
每一次都有说得通的机制、每一次都被推翻。共同的错是同一个：
**拿"改完之后好了"当证明**，而那些"好了"有一半是读数不稳，另一半是读错了对象。

### 2.6 ⚠️ 新增：先问"这个现象在什么环境下测出来的"

本轮推翻的两条缺陷，**错不在观察，在于观察是在一个带注入层和预览通道的宿主里做的，
而结论被当成了 `.dc.html` 格式本身的性质。**

换一个环境重测一次，比在原环境里二分十几轮便宜得多。

这条纪律对 Umbra Studio 自己也成立：`05` §2.1 明写了三条环境差异
（headless ≠ macOS Chrome、React 走本地副本、多文件走 http 不是双击），
后面凡是引用 `05` 的结论，适用范围以那一节为界。

### 2.7 ⚠️ 新增：反向验证之前，先证明仪器没被自己消音

这一条是 `2.4`（先校准仪器）的推论，但吃过一次亏才写出来，所以单列。

`00` §二十四 撤回了一条**真**判据（SVG 几何属性上的洞会在解析期报错），
撤回的依据是一次反向验证：4 份真实语料 + 8 种合成形态，`render_check` 全零告警。

`render_check` 里有一行静音，把 `attribute … Expected` 这一类控制台消息整段丢掉了
—— **那行是我自己写的**。也就是说反向验证用的仪器，恰好对准了要找的信号做了消音。

> **「量到零」有两种可能：世界是零，或者仪器是零。分不清就不能撤回判断。**

具体到做法：撤回一条判据之前，必须先证明仪器**能**报这一类 ——
拿一个已知必报的样本过一遍仪器，看得见才算仪器活着。
这和 `2.1`「判活只认 `1+1`」是同一个动作，只是对象从被测页换成了工具自己。

对应地，`render_check` 的新判据是：**凡是控制台真的说了的，工具都要说。**
分不清要紧不要紧的，就单独归一类说清楚（现在 `svg-parse` 就是这么一类），
**不能静音**。静音省下来的那点噪声，代价是整套验收证据出现一个看不见的洞。

## 三、仍然有效的六条校验

不管缺陷怎么重新定性，这六条检查都该做，理由各自独立于旧缺陷：

| 检查 | 独立理由 | code |
| --- | --- | --- |
| 洞取不到值 | 模型看不到控制台，必须结构化回报 | `E_HOLE_UNRESOLVED` |
| `dc-import` 目标不存在 | 空占位是最难查的一类失败 | `E_IMPORT_MISSING` |
| 标签配平 | 半截模板会渲染到屏上 | `E_TAG_UNBALANCED` |
| 注释含标签字面量 | 会把注释提前关掉 | `E_COMMENT_TAG` |
| 未知标签名 | 写错只会安静渲染成 0×0 | `W_UNKNOWN_TAG` |
| helmet 同 URL 重复 | 上一轮踩过整份 bundle 跑两遍 | `W_HELMET_DUP` |

`fixed` + `backdrop-filter` 那条虽然未测，也保留为 `W_FIXED_BLUR`——
代价是一条警告，收益是万一它是真的就不用再花一轮。
