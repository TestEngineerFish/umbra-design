## 一、文件格式

一份稿就是一个 `.dc.html`，双击可开。骨架固定：

```html
<!DOCTYPE html>
<html>
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<script src="./support.js"></script>     <!-- 运行时，与稿同层 -->
</head>
<body>
<x-dc>
  … 模板（HTML + 洞 + 控制流） …
</x-dc>
<script type="text/x-dc" data-dc-script data-props="{…JSON…}">
class Component extends DCLogic {
  state = { … };
  renderVals() { return { …给模板的值… }; }
}
</script>
</body>
</html>
```

三块：

| 块 | 作用 |
| --- | --- |
| `<x-dc>…</x-dc>` | 模板。普通 HTML，加 `{{ 洞 }}` 与 `<sc-if>` / `<sc-for>` / `<dc-import>` |
| `<script type="text/x-dc" data-dc-script>` | 逻辑类。普通 JS，类名固定 `Component`，继承 `DCLogic` |
| `data-props="…"` | props 元数据 JSON（HTML 转义）。驱动「可调参数」面板 |

⚠️ `type="text/x-dc"` 让浏览器**不执行**这段脚本，由运行时自己取出来 `new Function` 编译。
这是「双击即开、无构建」的关键——浏览器只认识 `support.js` 一个真脚本。

## 二、运行时（support.js）要做的事

按启动顺序：

### 2.1 引 React

从 CDN 取 React + ReactDOM（UMD 版，挂 `window.React`）。

⚠️ **Umbra Studio 默认走本地副本，不走 CDN。** 做法是在 `support.js` 之前注入
它自己的宿主钩子：

```html
<script>window.__resources = {
  "https://unpkg.com/react@18.3.1/umd/react.production.min.js": "./react.production.min.js",
  "https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js": "./react-dom.production.min.js"
};</script>
```

命中 `__resources` 时运行时用映射值作 `src` **且不加 SRI**，
所以**不需要改 support.js 一行**（依据见 `05` §1.1）。
离线包共 142 KB（10.7 + 131.8），**与稿同层**——`<script src>` 是相对文档解析的，
每个放稿的目录都要有一份，由 MCP 分发（`00` §三）。
这段注入块由 `write_draft` 在落盘时加，**不写进设计稿**（`00` §5.2）。

**不分发 `@babel/standalone`。** 它只在 `<x-import from="x.jsx">` 这一条路径上加载，
全库 27 份稿零使用，断开后实测照常渲染（`05` §五）。
将来若要引入 JSX / TSX 外部组件，必须补回它——现在不带是因为没人用，不是不需要。

### 2.2 解析模板

拿 `<x-dc>` 的 innerHTML，编译成 React 元素树。这一步做四件事：

1. **洞替换**：`{{ path }}` → 从 renderVals 的返回值里按点号路径取
2. **属性映射**：`class`→`className`、`for`→`htmlFor`、`onClick` 保持驼峰
3. **控制流展开**：`<sc-if>` / `<sc-for>` 编译成条件与 map
4. **子组件挂载**：`<dc-import>` 编译成一个懒加载的子树

### 2.3 编译逻辑类

`new Function('DCLogic', 'React', src + '; return Component;')` —— 注入两个全局，取回类。
**不能用 `eval` 在全局作用域跑**，否则多份稿之间 `const` 会互相撞名。

### 2.4 挂载

```js
ReactDOM.render(React.createElement(Host), document.body)
```

`Host` 是运行时自己的组件：持有 `Component` 实例，每次 `setState` 后重新调 `renderVals()`，
拿返回的对象去填模板。

### 2.5 流式渲染 —— ⚠️ 第二阶段，第一批不实现

> **第一阶段调用方是模型，一次性落盘，没有"边写边看"的人。**
> 而 `hint-*` 一整套语义正是流式渲染的配套，`04` 缺陷 #4 与旧自检第 7 条
> 都是它的并发症。所以第一批**语法保留、实现推后**：`hint-*` 属性解析但忽略
> （`03` §八）。存量稿一个字不用改。
>
> 下面这段描述 `support.js` 已有的流式行为，第二阶段给人和秘书用时再打开。

文件是一边写一边落盘的，所以运行时应当：
- 模板每收到一个完整标签就渲染一次
- 洞暂时取不到值时，用 `hint-*` 属性给的占位撑住布局
- `</x-dc>` 收到之后再编译逻辑类，然后整体重渲染一次

## 三、模块划分

```
support.js
├── loader        取 React、找 <x-dc> 与 <script data-dc-script>
├── parser        HTML → 元素树（含洞、控制流、子组件）
├── resolver      洞求值：按点号路径从 vals 取，取不到走 hint / 警告
├── compiler      逻辑类编译，注入 DCLogic / React
├── host          React 组件：state → renderVals → 填模板 → 渲染
├── importer      <dc-import> 的解析、取文件、缓存、children 透传
└── devtools      props 面板、主题切换、错误浮层   ← 第二阶段（01 §3.3）
```

MCP 层在这之外，是另一个进程（Node + TS），**不进 `support.js`**：

```
server/
├── tools/        工具实现（00 §五）
├── validate/     静态校验（00 §六）
├── render/       Playwright 渲染体检（00 §七）
├── snapshot/     语义快照与 diff（07）
└── serve/        静态服务（形态 A，01 §4.2）
```

## 四、关键设计决策

### 4.1 为什么模板和逻辑分开

模板是**给人看的**（实现侧要照抄取值），逻辑是**给机器算的**。
混在一起（JSX）会让模板里出现三目运算、`.map()`、模板字符串——实现侧就没法逐行照抄了。

规则：**模板里只允许点号路径，不允许任何表达式。** `{{ a + b }}` 一律不支持。
要算就在 `renderVals()` 里算好，起个名字暴露出来。

### 4.2 为什么洞只能是点号路径

如果洞里能写表达式，就必须在运行时带一个 JS 求值器，而且：
- 流式渲染时表达式可能引用还不存在的值 → 要做错误恢复
- 直接编辑功能没法反写（改了界面上的字，不知道写回哪）

限制成点号路径之后，**「这个字从哪来」永远是一个明确的键名**。

### 4.3 为什么样式只写在 style 属性上

不是审美偏好，是两条实际原因：

1. **流式渲染**：CSS 类要等样式表到齐才生效，inline style 跟着标签一起到，**立刻就画对**。
2. **取值可读**：实现侧看 `style="padding:10px 18px;background:var(--rail)"` 就能抄，
   看 `class="page-header"` 还要去翻样式表。

例外只有三样，必须放 `<helmet>` 里：`@font-face`、`@keyframes`、body 重置。

### 4.4 `<helmet>` 是什么

模板最顶部的一个特殊标签，内容会被搬进 `<head>`：

```html
<helmet>
  <link rel="stylesheet" href="_ds/…/tokens/colors.css">
  <script src="…/_ds_bundle.js"></script>
  <style>body{margin:0;background:#DEDBD5;} @keyframes umspin{to{transform:rotate(360deg)}}</style>
</helmet>
```

⚠️ **同一份文档里同一个 URL 只应加载一次**。本项目踩过：页稿和它引用的组件各写了一份
设计系统 bundle，路径写法不同（一个本层、一个上跳），于是成了两个不同 URL，
**整份 bundle 跑了两遍**。新框架建议：运行时按「解析后的绝对 URL」去重。

### 4.5 子组件：`<dc-import>`

```html
<dc-import name="../Components/窗口骨架" active="日志" hint-size="100%,100%">
  …这些 children 会传给子组件的 {{ children }}…
</dc-import>
```

| 属性 | 含义 |
| --- | --- |
| `name` | 目标 `.dc.html` 的路径（不带扩展名），相对于**当前文件所在目录** |
| `hint-size` | 加载完成前的占位尺寸，`宽,高` |
| 其它属性 | 变成子组件的 props，kebab → camelCase |
| children | 变成子组件的 `props.children` |

实现要点：
- **同一个文件被引 N 次，只取一次、只编译一次**，实例各自独立
- 取文件是异步的 → 未就绪时渲染 `hint-size` 的占位盒
- ⚠️ **路径解析必须以引用它的那个文件为基准**，不是以顶层文档为基准

### 4.6 props 元数据与可调参数面板

`data-props` 的 JSON 长这样：

```json
{
  "$preview": { "width": 520, "height": 320 },
  "kind":  { "editor": "enum", "options": ["empty","error"], "default": "empty", "tsType": "'empty'|'error'" },
  "title": { "editor": "text", "default": "还没有内容", "tsType": "string" },
  "onAction": { "editor": null, "tsType": "()=>void" }
}
```

- `editor` 非 null 的项渲染成一个控件，改了就重渲染
- `editor: null` 表示「这是回调 / 节点，不给面板」
- `$preview` 给独立打开时的画布尺寸
- `default` **只喂面板，不喂运行时** —— 运行时的兜底要写在 `renderVals()` 里（`P.x ?? 默认`）

## 五、目录与复用

**目录布局与租户配置的权威出处是 `00` §三**，这里只说复用规则本身。

要点：设计系统是**可插拔的项目输入**，Umbra 只是第一个租户。
`support.js` 与 React 本地副本在 `Umbra Studio/runtime/`，所有租户共用；
每个租户目录下 `_ds/` 的名字和位置固定，稿里用 `@ds` 别名引用，
由 `write_draft` 在落盘时展开成普通相对路径（`00` §3.2）。

三条规则：

1. **共用的值只放一份**。跨稿共用的常量与工厂进普通 `.js`，用经典脚本挂全局
   （`window.X = …`），**不要 ES module** —— `renderVals()` 是同步的，`import()` 是异步的，
   首帧就要用的值不能走要等的路。
2. **一份稿控制在 1,200 个静态元素标签以内，超 1,500 必须拆。**

   ⚠️ **依据已改。** 旧版写的是"超过约 1,500 浏览器就不渲染"，
   `05` §三实测推翻：6,514 个元素的稿完整渲染。
   现在的两条理由都是工程理由——175 KB ≈ 45 K token，模型一次输出不了；
   语义变更清单的粒度就是文件粒度（`00` §6.3）。
   Lighthouse 的 1,500 节点是**性能提示**，不是渲染上限，不要再当成技术限制引用。
3. **源码组织像 Web 项目，交付物不许需要构建。** 入口页 `index.dc.html` 由
   `build_index` 自动生成，不手写（`01` §4.2）。

## 六、⚠️ 相对旧框架要改掉的地方

**本表按 `05` 的实测重排过。** 前三行的旧定性已被推翻或无法复现——
保留它们是因为**要做的事没变，只是理由变了**，别再照旧理由设计。

| 旧框架的记载 | 现状 | 仍然要做的 |
| --- | --- | --- |
| 洞取不到值时整页卡死 | **未复现**（`05` §四） | 洞取不到只影响那一处；整值属性洞取不到时**该属性不设置**；诊断走 `E_HOLE_UNRESOLVED` |
| 渲染失败静默 | 成立，且在 MCP 场景下更要紧 | **结构化返回给调用模型**，不是"页面上显示"——模型看不到页面也看不到控制台（`01` §五 R2） |
| 大文件静默退回显示源码 | **推翻**（`05` §三），是旧宿主的预览通道 | 超阈值给 `W_ELEMENTS_*` 并附拆分点建议 |
| `dc-import` 路径解析对深层目录不稳 | 成立；但 `file://` 下全部失败是更大的原因（`05` §4.2） | 按引用方文件解析 + `E_IMPORT_MISSING` 显式报错；两层以上目录写测试 |
| 没有渲染耗时可见性 | 成立 | `render_check` 返回 `renderMs` / `nodeCount`（`00` §7.2）。**角标不做**——第一阶段没人看屏 |
