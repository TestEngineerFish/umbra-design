## 一、最重要的一条：引擎已经有了

`support.js` 不是旧框架的残骸，是**一份完整可用的运行时**。

| 项 | 读数 |

| 分段 | 18 个 `// src/*.ts`：react / parse / boot / expr / encode / compile / logic / component / bundled / cdn / external / atomics / helmet / pseudo / registry / runtime / stream-state / index |
| TS 源码 | **`Geek` 全库搜不到 `dc-runtime` 目录** |

TS 源码没有，但这份构建产物未压缩、分段清晰，**等于可读源码**。

### 1.1 它本来是跑在宿主里的

`support.js` 里有一组宿主注入钩子：

| 钩子 | 作用 |
| --- | --- |
| `window.__resources` | `{CDN URL → 本地 URL}` 映射。命中时用映射值作 `src`，**并且不加 SRI** |
| `window.__resourceBlobs` | `{URL → Blob}`，命中时直接读 Blob，不发网络请求 |
| `window.__dcUpdate` / `__dcBoot` | 宿主驱动的流式喂内容入口 |

这解释了 `04` §2.4 那一幕——「副本删完之后，那些警告仍然在印那些路径」：
**印那些路径的是宿主的注入表，不是页面的真实解析结果。**

**推论（判断，非结论）**：`04` 缺陷 #2「同一份文件有时渲染有时卡死，取决于怎么落盘」
的根因更可能在宿主侧（注入表与预览缓存），而不在落盘方式。
这一条**无法在 UmbraDesign 里复现或排除**，因为旧宿主不在我们手上。
处置见 §四。

### 1.2 它的外网依赖

| 资源 | 出处 | 何时加载 |
| --- | --- | --- |
| `react@18.3.1` UMD | unpkg，带 SRI | 启动时必加载 |
| `react-dom@18.3.1` UMD | unpkg，带 SRI | 启动时必加载 |
| `@babel/standalone@7.29.0` | unpkg，带 SRI | **仅 `<x-import>` 引 .jsx/.tsx 时**，见 §五 |
| `chart.js@4.4.1` | jsdelivr，**写在 `Umbra PC 端` 的 helmet 里** | 该稿加载时 |

前两项走 `__resources` 钩子就能换成本地副本，**不改 support.js 一行**。

## 三、缺陷 #3「超过约 1,500 元素静默不渲染」——**推翻**

### 3.1 读数

| 稿 | 大小 | 元素标签 | 打开方式 | 判活 | DOM 节点 | 耗时 | 控制台 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `Umbra 设计规范` | 226 KB | 1,524 | `file://` 双击 | **ALIVE** | 2,307 | ~3 s | **0 条** |
| `Umbra PC 端` | 1,525 KB | 6,514 | `http://` | **ALIVE** | 561 | 12.1 s | 1 条 404（`ios.css`，测试时未拷入） |

`Umbra PC 端` 的截图已核对：标题栏、侧边栏 14 项、联系人列、演示态胶囊两行、
消息气泡、图片槽、工具轨迹、输入区——**全部正常**。

**561 个节点不是渲染不全**，是 `sc-if` 只展开了当前那一个模块（聊天）。
6,514 个静态标签里绝大部分在未激活的分支里。

### 3.2 现象本身也排除了浏览器

旧文档记的失败样子是「不报错，退回成按页显示源码，还把中文显示成乱码」。

- 稿子头部有 `<meta charset="utf-8">`——Chrome 本地打开不可能乱码；
- `support.js` 一进来就 `hideRawTemplate()`——正常路径上模板不会露出来。

**乱码 + 显示源码 = 文件没有被当作 HTML 解析。** 这只能来自把它按 `text/plain`
（且未带 charset）发出来的一方，即旧宿主的预览通道。

### 3.3 处置

`01` §四的渲染规模一项、`04` 缺陷 #3、README 的相关表述**全部改写**。
阈值保留在 1,200 / 1,500，但**依据改成工程理由**（模型写不动 + diff 读不懂），
详见 `00` §6.3。

## 四、缺陷 #1「整值属性洞取不到 → 整页永远画不完」——**未复现**

### 4.1 读数

拿 `PC 空态.dc.html`（旧文档记的最小复现件）造两份：

| 版本 | `renderVals()` 里 | 判活 | DOM 节点 |
| --- | --- | --- | --- |
| 修复版 | `onAction: P.onAction ?? NOOP` | ALIVE | 29 |
| 裸 undefined 版 | `onAction: P.onAction`（单开时无人传，值为 `undefined`） | **ALIVE** | **29** |

两份读数**完全相同**。模板上确实有 `onClick="{{ onAction }}"`（第 28 行）。
`onSecondary` 同样去掉兜底，结果不变。

### 4.2 但确实测到了一条会挂的

**`dc-import` 在 `file://` 下必然失败。**

```
[dc-runtime] sibling fetch for "PC 折叠栏" threw:
  ./PC%20%E6%8A%98%E5%8F%A0%E6%A0%8F.dc.html  TypeError: Failed to fetch
  at ensureFetched (support.js:1651)
```

`support.js` 用 `fetch()` 取兄弟稿，**Chrome 不允许对 `file://` 发 fetch**
（`--allow-file-access-from-files` 也不管用，那个标志管 XHR 不管 fetch；
真实双击场景连标志都没有）。换成本地 http 起同一个目录，`dc-import` 立刻全部正常。

> **这是本轮唯一一条稳定复现的挂死原因，而四份旧文档里一条没提。**
>
> 它意味着 `01` §3.1 的 F1（双击即开）与 F4（组件复用）**在现行浏览器策略下互斥**。
> 这不是 bug，是安全策略，绕不过去。处置见 `01` §四「交付形态」。

它也顺带解释了 `04` 缺陷 #5「跨文件夹 `dc-import` 只写基名 → 静默空占位」：
在 `file://` 下**所有** import 都是空占位，与写基名还是写相对路径无关。
`http` 下写错路径仍会失败，所以 `E_IMPORT_MISSING` 这条校验要留（`00` §6.1）。

### 4.3 缺陷 #2 的处置

**未测，也无法测**（需要旧宿主）。但不必先查清根因：
`00` §5.2 已把 MCP 定为唯一写入口并强制归一化落盘（UTF-8 无 BOM / LF / 末尾单换行），
**这一条从工程上堵死了整类"落盘方式影响结果"的可能**，无论根因是什么。

`01` §六的验收第 5 条（三种落盘方式结果一致）**保留**，它现在是对归一化落盘的验收。

## 五、Babel 可以砍——**结论**

三条依据：

1. **代码路径唯一。** Babel 只在 `external.load()` 里 `kind === "jsx"` 时加载；
   `kind` 来自 `kindOf(u) = /\.(jsx|tsx)(\?|#|$)/i.test(u) ? "jsx" : "js"`；
   唯一调用入口是 `<x-import from="…">`。
   逻辑类（`<script type="text/x-dc">`）走 `new Function`，**与 Babel 无关**。
2. **全库零使用。** 27 份稿里 `from="…"` 零命中，`<x-import>` 一个都没有。
   （`Umbra 图标清单.dc.html` 里的 `icons.tsx` 是正文里的一句说明文字，不是引用。）
3. **断开实测。** 把 Babel 请求直接 abort，《设计规范》与《PC 端》**均 ALIVE**，
   控制台无 babel 相关输出。

离线包因此只需 React + ReactDOM，共 **142 KB**（10.7 + 131.8），省掉 3.1 MB。

> ⚠️ **将来若要引入 JSX / TSX 外部组件（`<x-import from="x.jsx">`），必须补回
> `@babel/standalone`。** 现在不分发它是因为没人用，不是因为它不需要。
> 这条已写入 `00` §二。

## 六、怎么重跑

1. 把租户目录整份拷到工作区
2. 从 npm 取 `react@18.3.1` / `react-dom@18.3.1` 的 `umd/*.production.min.js`
3. `page.addInitScript` 注入
   `window.__resources = { "https://unpkg.com/react@18.3.1/umd/react.production.min.js": "<本地 URL>", … }`
4. 起静态 http 指向该目录（**多文件稿必须走 http，见 §4.2**），打开目标稿
5. 轮询 `document.querySelectorAll('*').length` 到稳定
6. `waitForFunction("1+1===2")` 判活——**不看截图**（`04` §2.1）

这套流程就是 `render_check` 的实现（`00` §七）。
