## 一、⚠️ 最要紧：`ui/S1`–`S5` 这五份稿**不要重新生成**，只能增量改

这五份稿现在**不只是设计稿了** —— 里面有工具侧接真实数据的接线。
重新生成一遍会把它们全冲掉，那是这两天工作量的大头。

### 1.1 每份稿里现在有什么

| 稿 | 加了什么 |
| --- | --- |
| `S1-稿件索引` | `LIVE` 门控；读 `window.__UD_INDEX`；顶栏吸顶高度实测；`go()` 跳 `S2-…?file=` |
| `S2-单稿预览壳` | `LIVE` 门控；本地 API（诊断/变更/定位/改属性/回退）；**注入点选桥**；属性面板；版本回退 |
| `S3-诊断面板` | `LIVE` 门控；诊断与体检读数来自本地 API |
| `S4-变更清单` | `LIVE` 门控；变更来自本地 API |
| `S5-设计系统浏览器` | `hasApi()` 门控；token / 图标 / 组件契约来自本地 API，**检索在服务端做** |

### 1.2 那条门控是什么，为什么这么设计

**一份文件两种用法，不分叉。** 在 `ui/` 下直接打开 → 没有真实数据，
走你自带的 9 个演示态，设计评审照旧；被工具部署进项目目录 → 显示真实数据，
演示态那一行整行不出现。

判据分两种，各有理由：

```js
// S1 / S2 / S3 / S4 —— 它们必须知道「看的是哪一份稿」
const LIVE = new URLSearchParams(location.search).get("file");

// S5 —— 它是项目级的（token / 图标 / 组件），不需要知道哪一份
const hasApi = () => !!(typeof window !== "undefined" && window.__UD_API);
```

工具在落盘时注入两个全局：

```js
window.__UD_INDEX = { project: {…}, drafts: [ … ] };   // 索引数据
window.__UD_API   = { base: "http://127.0.0.1:<port>/__ud/", token: "…" };
```

### 1.3 你改的时候请遵守

1. **保留所有 `LIVE` / `hasApi()` 分支**。要改样式就改样式，
   不要把 `LIVE ? 真数据 : 演示数据` 这种三元拆掉
2. **不要往散文里写死数字。** 这个坑我们踩了四次 ——
   上面三格显示「洞 3」而下面一句写着「143 个洞全部解析到了」，两句话自相矛盾，
   而且它**看起来像真的**，比明显的假数据更糟。
   规矩：给人看的文字里凡带数字或源码片段，必须和同屏数据同源
3. 改完请跑一遍自查（§六）

### 1.4 一个你可能想动但**动不了**的地方

样式字面量**没有实时预览**。拖滑块时中间态用不了运行时自带的
`window.__dcSetProps(name, overrides)` —— 那条只管 props，样式字面量没有覆盖通道。
所以现在是「松手才落盘、iframe 重载才看到」。

**这是机制缺口，不是形制问题。** 如果你觉得手感不能接受，需要设计一条样式覆盖通道
（比如往 iframe 注入一段临时 `<style>`），那是一个新功能，请在 §五 第 4 项里给意见。

## 二、批量修：149 处洞写在「浏览器解析时就动作」的属性上

### 2.1 现象与原因

【实测】控制台报：

```
<path> attribute d: Expected moveto path command ('M' or 'm'), "{{ i.d }}".
```

值是**字面量 `{{ i.d }}`** —— 浏览器在解析 HTML 那一刻就对某些属性动手，
而那时洞还没被运行时替换。两类：

| 类 | 属性 | 后果 |
| --- | --- | --- |
| 会发请求 | `src` / `href` / `srcset` / `poster` | 去请求字面量 `{{ x }}`，每次加载留一个 404 |
| 解析时校验 | SVG 的 `d` / `points` / `viewBox` / `transform` / `cx` / `cy` / `r` / `x1`… | 控制台立刻报一条 error |

**两者都不影响最终渲染** —— 所以一直没人发现。但 `render_check` 会把它算进控制台告警，
按健康判据这些稿就**一直是黄的**。一条永远好不了的黄，比没有这条检查更糟，
所以工具侧新增了 `W_HOLE_IN_PARSED_ATTR`（warning 级，附改法）。

### 2.2 改法

**挂到 `data-*` 上，逻辑类里抄过去。** 静态值给一个合法但画不出东西的占位。

```html
<!-- ✗ 现在 -->
<path d="{{ i.d }}" stroke="currentColor"></path>

<!-- ✓ 改成 -->
<path data-icon-d="{{ i.d }}" d="M0 0" stroke="currentColor"></path>
```

```js
/* 逻辑类里加这两段。d 的占位用 "M0 0"：合法的 moveto，画不出东西，控制台干净。
   ⚠️ 占位**不能给空串**，空串同样报 Expected moveto。 */
syncIcons() {
  const list = document.querySelectorAll("path[data-icon-d]");
  for (let i = 0; i < list.length; i++) {
    const el = list[i], want = el.getAttribute("data-icon-d") || "M0 0";
    if (el.getAttribute("d") !== want) el.setAttribute("d", want);
  }
}
componentDidUpdate() { this.syncIcons(); }
```

挂载时也要抄一次（`componentDidMount` 里 `setTimeout(() => this.syncIcons(), 0)`）。
`S5-设计系统浏览器.dc.html` 已经按这个改完，可以直接抄那份的写法。

`src` / `href` 同理：静态值先写 `about:blank`（或一个占位路径），真地址由逻辑类设。
`cx` / `cy` / `r` 的占位给 `0`。

### 2.3 ⚠️ 但我建议你先考虑另一条路

143 处里绝大多数是**同一件事重复了一百多遍**：在稿里内联 SVG 画图标。

**更划算的改法：抽一个图标组件，用 `dc-import` 引。** 这样：

- 洞只出现在**一个文件**里，这条规则只需要遵守一次
- 图标名 → path 的映射集中，跟 `icons.json` 对得上
- 以后换图标源只改一处

这是**判断不是定论** —— 会多一层 `dc-import`，而 `Umbra PC 端` 已经引了 115 个子组件。
你更清楚这批稿的组织方式，选哪条你定。**但请不要两条都做一半。**

## 三、两个真缺陷（会静默失败，优先处理）

### 3.1 `任务.dc.html` 的错误卡拿不到 meta 与 actions

【实测】`PC 端/任务.dc.html` 与它的副本 `PC 端/Pages/任务.dc.html`，第 **291** 行：

```html
<dc-import name="PC 错误卡" … meta="{{ decideMeta }}" actions="{{ decideActions }}">
```

这两个洞在整份稿里**只出现这一次** —— `renderVals()` 里没有这两个键。
而 `PC 错误卡` 的 props 里它们是真的：

```
meta:    {label:string; value:string}[]
actions: {label:string; kind?:'primary'|'danger'|'ghost'; act?:()=>void}[]
```

所以那张「决策失败 · 模型调用被拒绝」错误卡**信息行是空的、一颗按钮都没有**，
而且**不报错、控制台干净**。属性洞解析不出时运行时会把整个属性丢掉，
一句告警都没有 —— 这是最安静的一类失败。

**要你定的是内容**：那张卡该显示哪几行信息（`meta`）、几颗什么按钮（`actions`）。
这是设计决定，我们不替你定。定了之后在 `renderVals()` 里补上这两个键即可。

## 四、两条新的格式规则（工具已经在查）

这两条都是实测踩出来的，写进了 `doc/06-写稿规则.md`：

### 4.1 §2.7 控制流标签不许落在 `table` / `select` 里 —— `E_CONTROL_IN_TABLE`（error）

`table` / `tbody` / `tr` / `select` / `optgroup` 只允许特定子元素。
HTML 解析器碰到**未知元素**（`sc-if` / `sc-for` / `dc-import` / `x-import`）
会把它**搬到外面去**（foster parenting），于是运行时在里面找不到它，
**一声不响地不渲染** —— 表头在、行是空的，没有报错，控制台干净。

**列表和表格都用 div + CSS grid。** 你的 `S1-稿件索引.dc.html` 全篇零个 `table`，
就是对的写法 —— 这条规则正是照它定的。

> 这条我们自己也踩过两次（工具生成的入口页、S2 的版本下拉），两次都是校验器抓的。

### 4.2 §2.8 解析时就动作的属性上不许写洞 —— `W_HOLE_IN_PARSED_ATTR`（warning）

见 §二。`style` / `title` / `class` / `aria-*` 这类解析时不动作的属性，写洞没问题。

### 4.3 不用管的：`W_HINT_IGNORED`（52 处）

`hint-*` 属性是**流式渲染**的配套，第一阶段没有流式，所以解析但忽略。
**存量的不用删**（语法仍然合法），新稿不要写就行。这一条不是缺陷。

## 六、改完怎么自查

工具侧的判据是**零误报**，不是零告警。你改完之后：

1. **每一份动过的稿单独过一次** `validate_draft`，看 `W_HOLE_IN_PARSED_ATTR` 是否归零
2. **`render_check` 是唯一的验收证据** —— `validate_draft` 全绿不等于能渲染。
   看 `alive: true`、`nodeCount` 合理、**控制台零 error、断网零外部请求**
3. **改完稿要重新体检。** 体检读数带源码 sha256，稿动一个字就回到「未体检」——
   工具不会拿旧读数替新文件背书
4. 五份壳改完，请分别用两条路各看一次：带 `?file=` 和不带（S5 是有无本地 API）。
   两条路都要**控制台干净、零 404**
