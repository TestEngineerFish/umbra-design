## 一、1.1 S1 行内撤销

交回：`ui/_incoming/S1-稿件索引.dc.html`（baseline `sha="e7749f0de6fdc653" sent="20260923-0255"`）。只加不减：`LIVE`、`pullStale`、`onRebuild`、演示态 1–14 全部原样。

### 形制

- 删除不弹确认。那一行原地塌成一条 32px 的齐边细条：垃圾桶图标 · `已移到回收站` · 文件名（mono、灰） · 右侧 `撤销` 描边小钮。
- 语法与 S2 / S7 的「已落盘 · 撤销」同一套（齐边、`currentColor` 描边钮、19px 高），色调用中性 `--tool-panel-2` / `--tool-text-2`，不用红也不用绿：已发生且可逆的事不报警。
- 5 秒后消失（`UNDO_MS`；S2/S7 是 3 秒，删整份稿读字要多一眼）。
- 墙视图同一条：卡片塌成等高虚线占位 + `撤销`，格子不跳。
- 同一时刻只塌一行。再删第二份时，第一份立即定稿，不叠两条撤销。
- 塌着的行不可打开（点击、Enter 都跳过）。
- 新增演示态 15「行内撤销」：排第一的稿停在塌行状态，不走计时器。

### 键（按这个接）

```
state.justDeleted : null | { file, title, at, error? }   // 当前塌着的那一行
state.trashed     : [{ file, title, at }]                // 本页会话里已定稿的删除，pool() 会滤掉
state.actionsFor  : null | file                          // 哪一行的 ⋯ 菜单开着（原来 openActions 没接）
```

方法：`deleteDraft(r)` / `undoDelete(file)` / `settleDeleted()`，统一走 `api(name, body)`。

### 接线口径

- `deleteDraft`：乐观。先塌行，再 `POST delete_draft { file }`。失败时塌行文字换成 `没删成：<message>`，不给撤销钮，5 秒后行放回。
- `undoDelete`：乐观。先把行放回，再 `POST restore_draft { file }`。失败时重新塌行，文字 `没恢复成：<message>。去回收站里找`。
- 两个接口都按 `rebuild_index` 同一套：`window.__UD_API.base + name`，头带 `x-ud-token`，返回 `{ ok, errors? }`。演示态下 `api()` 直接返回 `{ ok: true }`，不发请求。
- 真数据下 index 是静态注入的，定稿后靠 `trashed` 把行藏起来，不整页重载；回收站视图会把本次会话删的稿排在最前，点「恢复」走 `restore_draft`。
- 回收站计数 `trashCount` 在演示值上加 `trashed.length`；真数据的回收站计数你们原本怎么来就怎么来，替换这一行即可。

## 二、1.2 会话栏放左还是放右

**同意：做成开关，默认在左，稿件列表可收起。**
理由：会话是驱动改稿的输入源，放在阅读起点（左）符合「先说、后看」的顺序；用户从 ClaudeDesign 迁移过来肌肉记忆也在左。稿件列表是低频导航，收起后三栏退成两栏，正好对齐本尊。开关只存本地偏好，不进 project.json。
