# fixtures/ —— UmbraDesign 自己的回归基准

这里的稿**不是设计稿**，是工具的测试基准，**随工具仓库一起追踪**。

## 为什么要有它

回归本来跑在 `projects/` 下的真实语料上。但 `projects/` 是用户自己的项目、
不进这个仓库 —— 换台机器 clone 下来，回归根本跑不起来，工具也就没有
属于自己的判据。

更要紧的是：语料证明不了「**不该报的没报**」。误报是这套工具最贵的错
（一条假的必改项能让设计侧白改一百多处），而语料里不存在的写法，
再多语料也照不出来。

所以这里每一份稿都钉住**一条已经犯过的错**：文件名说的是结论，
`expect.json` 里的 `why` 说的是它哪一天怎么犯的。

## 判据

`expect.json` 里写的是**这份稿应该报出来的全部诊断码**，精确匹配：

- 该报的没报 → 回归失败（判据退化了）
- 不该报的报了 → 回归失败（误报回来了）

`codes: []` 的意思是「这份稿必须一条都不报」—— 那是这里一半稿存在的理由。

## 跑法

```
npm --prefix server run selftest     # 静态：基准 + 工具界面稿 + 语料（有就跑）
npm --prefix server run rendertest   # 渲染：要 chromium，见 fixtures/渲染/
```

## 加一份的时候

**只在真的犯过错之后加。** 加的时候写清三件事：文件名写结论、
`why` 写哪一天怎么犯的、`codes` 写精确的期望。没犯过的错不要预先设防 ——
那会攒出一堆没人看得懂来历的用例。
